1. THE BOOK (no matching yet)
-----------------------------
STATUS: DONE (include/engine/book.hpp, src/engine/book.cpp, tests/book_test.cpp,
24 tests; 119/119 total, also under make test-asan).

[X] Two sides: bids and asks, each a set of price levels.
    -> bids: std::map<price, std::list<id>, std::greater>; asks: std::map<price, std::list<id>>
[X] Price level = all resting orders at one price, in time priority
    (sequence number order). Front of the queue trades first.
[X] add(order): only New/PartiallyFilled LIMIT orders rest. Insert at the
    back of its level; create the level if it doesn't exist.
    Market orders never rest (they're final after matching).
    -> also refuses duplicates; handle = iterator returned by list::insert.
[X] remove(order): take it out of its level; delete the level if it's now
    empty. Used by: Cancel, the old version on Replace, and fully filled
    orders during matching.
    -> O(1) via orderHandles (internal ID -> side, price, list iterator).
[X] bestBid / bestAsk: the top level of each side, or "none" if empty.
[X] Replace in the book (uses Order::replace's result):
      - old version: remove from the book.
      - new version, priority KEPT (same seq): takes the old version's
        place in the queue, not the back.
      - new version, priority LOST (fresh seq): back of its (possibly new)
        price level.
    -> replaceInPlace (kept) / remove + add (lost).
[X] FIX replaceInPlace: `auto orderList = it->second;` makes a COPY of the
    level's list. Inserting/erasing with handle.it (an iterator into the
    REAL list) on the copy is undefined behaviour; it only works by accident
    with this standard library. Use a reference (auto&) like remove() does.
    -> fixed: auto& in every branch.
[X] Book-level queries for tests: levelCount, prices (best first),
    idsAt (front first), contains, size.
    (Total quantity at a price needs the store; add it with market data.)

Book invariants (checkBook in tests/book_test.cpp, after every operation):
[X] An order is in the book  <=>  its state is New or PartiallyFilled.
[X] No empty price levels.
[X] Within a level, sequence numbers strictly increase front to back.
[X] Every order sits at the level matching its own price and side.
[X] Not crossed: bestBid < bestAsk whenever both exist (holds trivially

2. MATCHING
-----------
Decisions: docs/design.md section 8 (free function, trade record, store
first, replace through match, no self-trade prevention, Bug returned).

STATUS: DONE (include/engine/matching.hpp, src/engine/matching.cpp,
tests/matching_test.cpp, 32 tests; 164/164 total, also under make test-asan).

Hints:
  - Precondition checks come first in match (unknown / not live / already in
    book -> Bug with no event, nothing changed, no trade ID used).
  - Each step: best opposite price -> FRONT ID of that level -> store.find.
    If the store doesn't have it or it isn't live -> Bug (book and store
    disagree). idsAt() copies the whole level, which is fine for now; a small
    book method returning just the front ID is a cheap improvement.
  - Any apply outcome other than Accept -> Bug with that order and event.
  - The trade ID is taken (and nextTradeId incremented) only for a real trade.

[X] Crossing: an incoming order can trade if
      - buy limit:  price >= bestAsk
      - sell limit: price <= bestBid
      - market:     the opposite side is not empty
[X] The match loop, for an incoming (aggressor) order:
      while it has remaining AND it crosses the best opposite level:
        - take the FRONT order of that level (the resting order)
        - trade qty   = min(aggressor remaining, resting remaining)
        - trade price = the RESTING order's price (price improvement goes to
                        the aggressor)
        - apply a fill to BOTH orders through Order::apply
          (PartialFill or FullFill: let fill qty vs remaining decide which;
          a Bug outcome here means a matcher bug -> fail-stop)
        - if the resting order is now Filled, remove it from the book
    then:
      - limit aggressor with remaining  -> rests in the book (add)
      - market aggressor with remaining -> MarketNoLiquidity -> Cancelled
[X] Market buy walks asks from the lowest price up; market sell walks bids
    from the highest price down. Each level fully, front to back, before
    moving to the next price.
[X] Record each trade (both order IDs, price, qty) for the execution
    reports and output log in step 3.

Matching invariants and tests:
[X] After every incoming order: book not crossed.
[X] Quantity conservation: per trade, both sides' filled go up by the same
    qty; across a whole test, total bought == total sold.
[X] A market order is always final (Filled or Cancelled) after matching and
    never in the book.
[X] Price-time priority: at one price, the earlier order (lower seq) fills
    first; a better price fills before a worse one regardless of time.
[X] Scenarios to cover:
      - no cross: limit rests, book unchanged otherwise
      - exact match: both Filled, level removed
      - aggressor larger than one resting order: walks the queue
      - aggressor walks several price levels
      - aggressor partially fills then rests (limit)
      - market partially fills then Cancelled (no liquidity)
      - market into an empty side: New -> Cancelled
      - cancel / replace of a resting order, then matching respects the
        new queue position

Tidy (optional, no behaviour change):
[X] Check the MarketNoLiquidity apply outcome; non-Accept -> Bug (incoming

[-] Merge the identical Buy/Sell cases: work out the opposite side and best

    -> kept separate by choice; a comment in match() notes they could merge.
[X] Remove the stale "PLACEHOLDERS" comment at the top of matching.cpp.
[X] Pass validReplace = true (not false) to fills; fills ignore it, but

4. POSSIBLE OPTIMIZATIONS (come back after benchmarks; NOT now)
----------------------------------------------------------------
Rule: change one thing at a time, keep every test green, and measure before
and after (p50/p99/p99.9 + throughput). Record each result in
docs/benchmarks.md, including the ones that didn't help.

[ ] Queue holds POINTERS to orders instead of IDs: saves a hash lookup per
    order touched during matching. Needs a store whose elements never move
    (node-based map, or a pool/arena), so pointers stay valid.
[ ] Intrusive linked list: the order itself carries prev/next links, so a
    level needs no separate list nodes (no allocation per resting order,
    better cache behaviour). Handle = the order itself.
[ ] Price levels in an ARRAY indexed by price tick (offset from a base price)
    instead of an ordered map: O(1) level lookup. Needs a bounded price range
    and a way to find the next non-empty level fast (e.g. a bitmap).
[ ] Cache the best bid/ask level instead of asking the map each time.
[ ] Object pool / arena for Orders and list nodes: no malloc/free on the hot
    path (allocation shows up in the p99.9 tail).
[ ] Flat hash map (open addressing) instead of std::unordered_map for the
    two lookups: fewer cache misses.
[ ] Smaller order record: drop or move fields matching never touches
    (hot/cold split) so more orders fit in cache.
[ ] Matcher: idsAt() copies a whole price level just to read its front ID.
    A book method returning only the front ID (or a pointer) avoids it.
[ ] contains()-then-lookup patterns hash twice; one find() is enough.
[ ] Hash-map rehash spikes (found by the benchmark, part 3): the slowest
    requests (~1-9 ms) land at request #172829, #345391, #691359: each
    about double the last. That's a std::unordered_map (store, client-ID map
    or book handles) growing and rehashing everything at once. Part 4 found
    TWO doubling series (#172829/#345391/#691359 and #401996/#809401): two
    maps. Fix to try: reserve() capacity up front, or a map that grows
    incrementally. Details: docs/benchmarks.md.
[ ] parseRequest: stringstream + a std::string per token/key/value = several
    allocations per input line. Split the string_view in place instead
    (find(' ') / substr on the view) and look keys up without copying.
